# Риски и известные ограничения

Статус: V1 / локальный релиз. Документ фиксирует открытые риски, которые не были
полностью закрыты на момент релиза, и рекомендации по их снятию.

---

## 1. Высокие

### 1.1. Ручной смоук на реальных устройствах не выполнялся
Автоматические проверки (юнит-интеграционные тесты, Playwright E2E, API-смоук)
прошли, но полный матч вручную в браузере с несколькими телефонами по реальной
локальной Wi-Fi сети не проводился.

**Рекомендация:** перед реальной партией выполнить сценарий из §150 ТЗ на
компьютере + 2-4 телефонах: создать комнату, показать QR, подключить игроков,
сыграть полный матч, проверить refresh, временный disconnect Wi-Fi и
перезапуск приложения.

### 1.2. Приложение не поставляется с контентом
Built-in мемы и ситуации не включены в дистрибутив. По ТЗ §117 ответственность
за лицензирование встроенных ассетов решается отдельно от программной
архитектуры. Без загруженного контента команда `START_GAME` запрещена
(`NOT_ENOUGH_MEMES` / `NOT_ENOUGH_SITUATIONS`).

**Рекомендация:** либо добавить лицензионный ContentPack с бандлом мемов/ситуаций,
либо явно инструктировать хост загрузить контент до начала игры.

### 1.3. Проект не имеет истории версий
До этого коммита репозиторий Git не существовал. История изменений начинается
только с начального коммита.

## 2. Средние

### 2.1. E2E-тесты накапливают глобальное состояние
Три Playwright-спека выполняются последовательно против одного сервера.
Мемы и ситуации — глобальные сущности и копятся между тестами (по замыслу).
При необходимости изоляции стоит поднимать отдельный сервер/БД на каждый спек.

### 2.2. Live-таймауты проверены только юнит-тестами
Планировщик таймаутов (`StartTimeoutScheduler`) реализован, но сценарии
«Ready vs Timeout», «Vote vs Timeout» на живом сервере с ненулевыми таймерами
не прогонялись.

**Рекомендация:** прогнать игру с `*TimeoutSeconds > 0` на реальной партии и
убедиться, что `TIMEOUT_PHASE` срабатывает и фаза переходит штатно.

### 2.3. Конкурентный вход не проверен под нагрузкой
Сериализация `JoinRoom`/`Reconnect` добавлена (комната-лок + транзакция), но
массовый одновременный вход игроков (например, все сканируют QR одновременно)
под нагрузкой не тестировался.

## 3. Низкие

### 3.1. `lucide-vue-next` объявлен deprecated
Рекомендуется миграция на `@lucide/vue`. Некритично для V1.

### 3.2. WebP-оригиналы перекодируются в PNG
Нет чистого Go-энкодера WebP, поэтому `mimeType` для WebP-загрузок становится
`image/png`. Отображение корректно, но оригинальный формат не сохраняется.

### 3.3. Сессии без срока действия
Player-сессия живёт, пока не отозвана (`revoked_at`), экспирации нет.
Для доверенной LAN приемлемо, но утечка cookie = долгосрочная компрометация.
При желании добавить `expires_at`.

### 3.4. Admin-токен хранится в памяти как есть
В отличие от player-сессий (SHA-256), admin-токен в `AdminManager` не
хешируется. Только в памяти, короткоживущий. Защита по глубине — хешировать.

### 3.5. Отсутствует Origin-проверка WebSocket
`coderwebsocket.Accept` использует `InsecureSkipVerify: true`. Чужой сайт может
открыть read-only screen-подписку; игровые снапшоты защищены HttpOnly cookie.

### 3.6. Публичное состояние комнаты доступно по коду
Любой клиент в LAN может запросить public projection любой комнаты по её коду.
Код комнаты — единственная изоляция. Для локальной партии приемлемо.

## 4. Архитектурные замечания

### 4.1. Фаза игры частично живёт в памяти
`agg.Phase` / `agg.PhaseDeadlineAt` персистятся в БД и восстанавливаются при
старте (покрыто тестами restart/deadline recovery). Любой рассинхрон между
памятью и БД = неверная валидация фазы. При изменении кода следить, что фаза
сохраняется в том же коммите, что и состояние.

### 4.2. `SaveAggregate` перезаписывает дочерние строки
Подход delete + reinsert для дочерних сущностей игры. Корректно и FK-безопасно,
но тяжелее инкрементальных записей. На объёмах локальной партии некритично.

---

## 5. Чек-лист перед реальной партией

- [ ] Загружено достаточно мемов (≥ `max(N×H, N+(N-1)×H)` активных) и ситуаций.
- [ ] Игра с таймерами > 0 доведена до конца без зависаний.
- [ ] Refresh смартфона и временный Wi-Fi disconnect не дублируют игрока.
- [ ] Выход HOST передаёт роль старшему активному игроку.
- [ ] Перезапуск приложения восстанавливает игру из SQLite.
- [ ] `/host` недоступен с чужого устройства в LAN (нет admin-прав).
